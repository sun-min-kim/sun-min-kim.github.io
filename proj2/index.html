Part 1.1: Convolutions from Scratch

Implementation

The following is the code for the convolution I implemented myself. Both first flip the kernel and add zero padding before sliding the kernel over every pixel. The first code is my approach which made use of four for-loops, looping over every pixel, and then over every pixel within the kernel for each pixel. For the two for-loop approach, I looped over every pixel and then simply calculated all of the pixels within the kernel at once instead of looping over each individual one.

def four_loop_convolution(image, kernel):
    image_height, image_width = image.shape
    kernel_y, kernel_x = kernel.shape
    kernel = np.flip(kernel) # Flip filter
    output_image = np.zeros((image_height, image_width))
    padded_image = np.pad(image, ((kernel_y // 2, kernel_y // 2), (kernel_x // 2, kernel_x // 2))) # Pad image by kernel // 2 on all edges

    for y in range(image_height):
        for x in range(image_width):
            total = 0

            for ky in range(kernel_y):
                for kx in range(kernel_x):
                    kernel_value = kernel[ky, kx]
                    total += padded_image[y + ky, x + kx] * kernel_value

            output_image[y, x] = total

    return output_image
def two_loop_convoluiton(image, kernel):
    image_height, image_width = image.shape
    kernel_y, kernel_x = kernel.shape
    kernel = np.flip(kernel) # Flip filter
    output_image = np.zeros((image_height, image_width))
    padded_image = np.pad(image, ((kernel_y // 2, kernel_y // 2), (kernel_x // 2, kernel_x // 2))) # Pad image by kernel // 2 on all edges

    for y in range(image_height):
        for x in range(image_width):
            kernel_covered = padded_image[y:y + kernel_y, x:x + kernel_x] # Section of image covered under kernel
            kerneled_pixel = kernel_covered * kernel
            output_image[y, x] = np.sum(kerneled_pixel)

    return output_image

Comparison with scipy.signal.convolve2d

The four for-loop approach ran the slowest at 8.157 s. The two for-loop approach was significantly faster at 0.958 s, just over 8 times faster. This is probably because the four for-loops go over every pixel, and for every pixel, every pixel covered by the kernel, while the two for-loops are faster because numpy does all of the math inside. The built-in scipy method is the fastest, running at 0.044 s. For boundaries, the for-loop methods I wrote zero-pad, meaning a black border is added. Scipy's method also zero-pads by default (boundary="fill"), but it can instead mirror ("symm") or wrap ("wrap") the border.

The first 9×9 kernel filter averages out each pixel with its neighbors, effectively blurring the image. Dx represents the change in brightness going left to right, while Dy represents the change in brightness going top to bottom. This means that Dx highlights vertical edges while Dy highlights horizontal edges.

Part 1.2: Finite Difference Operator

∂I/∂x represents the image convolved with Dx and ∂I/∂y represents the image convolved with Dy. The gradient magnitude is computed as √(dx² + dy²), which represents the edge strength in any direction (vertical, horizontal, or diagonal).

Binarized Edge Image

For the threshold, choosing one that is too low leaves in a lot of speckles, like the ones from the grass that can be seen in 0.15, while a higher threshold may cause actual edges to start vanishing, like the background in 0.35. Because of this, I chose a threshold of 0.25, which had a good balance between removing specks and keeping edges. This way, the cameraman's edges remain while minimal grass specks appear.

Part 1.3: Derivative of Gaussian (DoG) Filter

Gaussian Smoothing First

To build the Gaussian, I made use of the built-in cv2.getGaussianKernel function to get a 1D kernel, and then calculated the outer product with the transpose of itself. Here, I used σ = 1 and a kernel size of 7. Before taking the derivative, I blurred the image first with the Gaussian kernel and then applied the steps from 1.2 to get a gradient magnitude.

A big difference I see is that this approach is a lot smoother, with the specks in the grass from Part 1.2 not being present. Additionally, the edges themselves are more defined compared to 1.2, where they are fragmented and sharp. For the threshold, I used 0.1. A lower value could be used compared to 1.2 because the Gaussian blur already smooths out the small changes in brightness which appear as specks in Part 1.2.

DoG Filters

Single Convolution with DoG

The DoG is the Gaussian convolved with either Dx or Dy. This allows us to only do one convolution on the image instead of two separate ones. As you can see, the result from this is the same as earlier, as the math itself is the same for each process: we are simply just combining the filters before we do the convolution, letting us only do it once.

Part 2.1: Image "Sharpening"

Unsharp Mask Filter

In this section, we use the Gaussian kernel as a low-pass filter to keep only the smooth parts of the image. By subtracting this image from the original image, we obtain a high frequency image which highlights the edges and textures in the image. By adding the high frequency image (scaled by α) to the original image, we can effectively sharpen the image by making details like edges and textures become more pronounced. This can all be combined into one kernel: (1 + α) × identity − α × Gaussian, where the identity kernel is all zeros with a one in the middle. Additionally, we apply it to each color channel separately to preserve the color of the image.

Part 2.2: Hybrid Images

In the following section, we create hybrid images. To do this, we apply a low-pass filter on the image that will be visible from afar, and a high-pass filter on the image that will be visible up close. Both make use of a Gaussian. By adding these two images together, we end up with an image where both are visible but from different distances. To do this, I also made use of the provided starter code to align the images.

Part 2.3: Gaussian and Laplacian Stacks

In the following images, I created a Gaussian stack and a Laplacian stack of an image of an apple and an orange. The Gaussian stack was made by repeatedly blurring the image while not downsampling (as opposed to the pyramid in Project 1), while the Laplacian stack was made by subtracting the next level of the Gaussian stack from each level, essentially creating a series of images showing the difference between each level in the Gaussian stack (or an image of the lost details). Level 0 shows the original image with finer detail while level 5 shows the image heavily blurred.

Part 2.4: Multiresolution Blending

In this section, we make use of the Gaussian and Laplacian stacks again, but to blend two images together, we also make use of a Gaussian stack of a mask. In the example of the oraple, the mask is simply split by a straight vertical line, which we create a Gaussian stack of in order to create the effect of blending. As a result, the two images blend together at the middle instead of having a hard, straight change from apple to orange.

Seoul: Day to Night (Wavy Seam)

In this example here, I created a blend of Seoul's skyline during the day and night. For the mask itself, I made use of a wavy mask which was calculated using a sine wave seam. In this case, the amplitude chosen was 60 pixels and the period 40 pixels. This was the formula used: column = middle + 60 × sin(2π × row / 40).

My Face on the Sun (Irregular Mask)

In this last example, I created a blend between my face and the sky, replacing the sun with my face (since my name is "SUN" Min). The blend then allowed my face to blend into the sky and the rays shining from the sun.

Laplacian Stack of My Favorite Blend

Reflection

Through this project, one thing that was highlighted to me was the prevalence/simplicity of the actual math that went behind modifying these images, often just involving basic arithmetic. For example, sharpening is just original + α × (original − blurred). The various different image manipulation tactics were also extremely fun to learn, especially being able to experiment with different images of our choosing, creating some funny final images. I also really enjoyed learning about using Gaussian stacks and Laplacian stacks, which also were just repeatedly subtracting a blurrier version of the image from the previous one. This project also really made me think about images as just individual pixels that can be manipulated, contrasting what we see every day through our own human eyes.
